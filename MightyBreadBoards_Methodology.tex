\section{Proposed Method}
This project is about a calibration method using stacked ensemble. To gather data necessary for the machine training, the proposed project uses an Air Monitoring System built with a low-cost sensor that can detect Particulate Matter as the device in test. Then it uses DENR standard PM monitoring system to serve as the calibration reference. The proposed model can read PM every 3 minutes and display it to the web and store it in a csv. The system uses an ESP32 Microcontroller to run the machine learning model to calibrate the readings.   

Figure 3.1. shows the simplified block diagram of the proposed Air Monitoring System. As shown in the diagram, the sensor detects the Particulate matter then passed to the processor where the data is processed. After processing, the processed data is then passed to the cloud where it can be accessed by a user device.

\subsection{Algorithm}
Figure 3.6 shows the architecture of the proposed stacked ensemble training model. The training process adopts a two-level configuration. The primary dataset is used to train the Random Forest Regression (RFR) and Support Vector Regression (SVR) as the Basic learners. Once trained, these base models are tested with another dataset, the prediction of these base models are paired with the reference values and are then used to train the Meta learner. After the Multiple Linear Regression (MLR) is trained, another dataset is passed to validate the performance of the stack ensemble.

\begin{figure}[htbp]
	\centering
	\includegraphics[width=0.9\textwidth]{Stack enseble architecture - training.png}
	\caption{Stack enseble architecture - training} 
	\label{fig:Stack enseble architecture - training}
\end{figure}

Figure 3.7 show the architecture of the stack ensemble in operation. During real-time prediction, the sensor inputs are simultaneously fed into the basic learners (RFR and SVR). Each base model generates a prediction based on the raw environmental and particulate readings. These predictions are then passed as input features to the meta learner (MLR). The MLR model applies its learned regression weights and intercept to create its own predictions which is considered as the calibrated final output.

\begin{figure}[htbp]
	\centering
	\includegraphics[width=0.95\textwidth]{Stack enseble architecture - operation.png}
	\caption{Stack Ensemble Architecture - Operation} 
	\label{fig:Stack Ensemble Architecture - Operation}
\end{figure}

To gather the dataset for the training, an air monitoring system is designed to gather and log data to the ThingSpeak. Figure 3.8 shows the flowchart of the data gathering, it starts with setting the channel id and write API of the ThingSpeak channel. Then it takes the sensor readings of RRH62000 and stores it into variables. The stored values are then sent to the ThingSpeak and after 3 minutes the loop starts again from reading the sensor values of RRH62000.

Figure 3.9 shows the program flowchart of how the stack ensemble is trained. It starts with importing the dataset using pandas. A variable named \textit{f\_train} is assigned with the dataset of the basic model while \textit{df\_train} is assigned with the dataset for testing the basic learner. Then a variable \textit{feature\_cols} is created to hold the column names of the input features and \textit{target\_col} for the target columns. Then another varaible is created to segregate the input features and target of the dataset for both the training and testing. X\_train and X\_test is the variable assigned to hold the dataset of the input features for the training and testing, y\_train and y\_test is assigned to hold the dataset of the target values for the training and testing. Then the RFR, SVR, MLR are trained using the imported dataset.

Using the \textit{y\_test} and \textit{y\_pred} the MAE, RMSE and R$^2$ are calculated and plotted into a scatter plot.

\subsection{Circuit Configuration}
Figure 3.13 shows the actual circuit configuration of the Air Monitoring System. The RRH62000 sensor is configured to I2C mode by connecting the Sel pin to Gnd and is connected to the ESP32 via I2C. The MCU is powered by either a 2S liFePo4 battery or a type-C charger via buck converter.  The circuit has two switches, S3 makes the MCU take power from the type-C and S4 connects the battery to the type-C to charge it. Under normal operation both switches are turned on so that the MCU can have an uninterruptable supply even if the type-C is removed.
